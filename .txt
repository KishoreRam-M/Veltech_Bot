[FILE]: `server/cache/l3_chunk.py`  
[LINE]: 9, 17, 27  
[SEVERITY]: Critical  
[TYPE]: Bug  
[PROBLEM]: `asyncio.Lock` bound to the main event loop crashes when called from `ThreadPoolExecutor` threads.  
[ROOT CAUSE]: `retrieve_knowledge` and `translate_query` use `asyncio.run()` in threads, which spins up a new event loop. When `l3_cache` attempts to acquire `asyncio.Lock`, it throws `RuntimeError` because the lock is attached to the main Uvicorn loop.  
[FIXED CODE]:
```python
import threading
from server.config import L3_TTL_SECONDS

class L3ChunkCache:
    def __init__(self):
        self._store = {}
        self._lock = threading.Lock() # Fix: Use thread-safe locking instead of async-loop locking

    async def get(self, domain: str, query_hash: str) -> list | None:
        k = self._key(domain, query_hash)
        with self._lock: # Fix: standard context manager
            entry = self._store.get(k)
```
[EXPLANATION]: Python's `threading.Lock` is globally thread-safe and loop-agnostic, meaning it can be acquired safely across Uvicorn's main loop and any `concurrent.futures` thread loops used by CrewAI tools.

[FILE]: `server/pipeline/session.py`  
[LINE]: 70-78  
[SEVERITY]: High  
[TYPE]: Performance  
[PROBLEM]: `_cleanup()` performs an O(N) iteration over all active sessions on every single chat request.  
[ROOT CAUSE]: The dictionary iteration happens synchronously blocking the main thread when `session_manager.get_or_create()` is invoked. At 10,000 active sessions, this halts the FastAPI event loop for several milliseconds on every single API call.  
[FIXED CODE]:
```python
    def _cleanup(self):
        now = time.time()
        if not hasattr(self, '_last_cleanup'):
            self._last_cleanup = now
        if now - self._last_cleanup < 60:
            return
        self._last_cleanup = now
        expired = [
            sid for sid, s in self._sessions.items()
            if now - s.last_active > self._ttl
        ]
        for sid in expired:
            del self._sessions[sid]
```
[EXPLANATION]: Throttling the O(N) cleanup iteration to a maximum of once per 60 seconds drastically reduces the amortized cost per request, freeing the event loop.

[FILE]: `server/app.py`  
[LINE]: 298  
[SEVERITY]: Medium  
[TYPE]: Bug  
[PROBLEM]: Resource leak where STT temporary `.webm` audio files are never deleted if transcription fails.  
[ROOT CAUSE]: The `os.remove(audio_path)` was nested inside the `try` block but after `await transcribe(audio_path)`. If `transcribe()` threw an error, execution jumped directly to the `except` block, bypassing file deletion entirely.  
[FIXED CODE]:
```python
    finally:
        if audio_path and os.path.exists(audio_path):
            try:
                os.remove(audio_path)
            except Exception:
                pass
```
[EXPLANATION]: Placing the `os.remove` into a `finally` block guarantees that temporary user audio files are wiped from the disk regardless of successful transcription, timeout, or model failure, preventing SSD bloat.
